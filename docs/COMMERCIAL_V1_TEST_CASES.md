# AI 文创 V1 商业闭环测试用例

版本：V1 MVP

目标：验证“对话创作 -> 报价 -> 接受报价 -> 打样费支付 -> 生产处理 -> 代销申请”的核心链路，确认用户隔离、状态流转、支付幂等和版权提示满足上线验收要求。

## 1. 测试范围

覆盖：

- 小程序登录和权限
- 对话式创作及会话数据保存
- 作品库、商品模板和产品化申请
- 后台人工报价及用户接受报价
- 打样费微信支付、回调和重复操作
- 生产申请、后台审核和状态查询
- 代销申请、版权确认和渠道目录
- 失败重试、越权访问、重复提交和异常状态

不覆盖：真实供应商接口、真实物流接口、自动分成结算、正式景区采购商城。这些属于后续版本或需要真实业务资料后验收。

## 2. 测试环境

### 2.1 环境要求

- 后端服务已启动，数据库迁移已执行。
- 小程序开发版已连接当前测试后端。
- 微信支付使用测试商户配置或人工收款二维码，不使用生产金额做测试。
- 测试商品至少有一条 `published=1` 且 `supply_status` 不为 `suspended` 的记录。
- 测试商品建议使用：`alloy-magnet`，名称为“合金冰箱贴”。

### 2.2 测试账号

准备三个账号：

| 编号 | 角色 | 用途 |
|---|---|---|
| U01 | 普通用户 A | 创建作品、申请报价、支付打样费 |
| U02 | 普通用户 B | 验证数据隔离和越权拦截 |
| A01 | 运营管理员 | 填写报价、审核代销、处理生产 |

测试账号必须使用脱敏手机号和邮箱。禁止把微信私钥、APIv3 Key、SMTP 授权码写入测试文档或提交 Git。

### 2.3 测试数据

- U01 至少有 1 个已生成作品，作品归属 U01。
- U02 至少有 1 个已生成作品，作品归属 U02。
- `alloy-magnet` 商品模板存在且可见。
- 至少有 1 条启用的渠道目录记录，合作状态为 `directory_only`。
- 至少有 1 条真实或测试供应链报价参数，供 A01 填写。

## 3. 用例状态说明

- 未执行：尚未测试
- 通过：实际结果符合预期
- 失败：实际结果不符合预期，必须记录日志、账号、请求参数和截图
- 阻塞：环境或第三方服务不可用，不能判定代码通过

## 4. 主流程用例

| 编号 | 优先级 | 操作 | 预期结果 |
|---|---|---|---|
| C-001 | P0 | U01 登录小程序并进入首页 | 登录成功，只看到 U01 自己的用户信息；不显示密码、SessionKey 或支付密钥 |
| C-002 | P0 | 进入“开始对话式创作” | 页面可打开，显示模式选择：产品模板、文字灵感、图片灵感 |
| C-003 | P0 | 选择产品模板 -> 合金冰箱贴 | 产品、材质和工艺选项正常显示，不能选择已下架商品 |
| C-004 | P0 | 依次填写灵感、材质、风格、颜色、用途 | 每一步可继续；刷新或返回后会话数据可恢复 |
| C-005 | P0 | 完成每一步后查询会话详情 | 会话事件按顺序保存，且只属于 U01 |
| C-006 | P0 | 提交 AI 提示词优化 | 返回可执行提示词；失败时显示可重试，不丢失已填信息 |
| C-007 | P0 | 生成产品图并保存作品 | 生成结果可预览，作品进入 U01 作品库，保存失败有明确提示 |
| C-008 | P1 | 选择“生成多视图” | 生成结果与当前作品关联，不创建无主作品 |
| C-009 | P1 | 点击 3D 建模 | 小程序提示到电脑端预览，不能显示空白 3D 页面或伪成功状态 |
| C-010 | P0 | 作品页进入商品化申请 | 自动带入当前作品，商品模板可选择，用户不能提交他人作品编号 |
| C-011 | P0 | 选择“申请报价/打样”，数量填 1，确认版权声明后提交 | 创建唯一报价单号，状态为 `new`，申请记录可在小程序查看 |
| C-012 | P0 | 不勾选版权确认直接提交 | 提交失败，明确提示必须确认版权；数据库不产生申请记录 |
| C-013 | P0 | A01 查看报价申请并填写单价、总价、交期 | 状态变为 `quoted`；金额和交期保存，操作人和审核时间留痕 |
| C-014 | P0 | U01 刷新申请记录 | 能看到报价、总价、交期和运营备注，金额以服务端数据为准 |
| C-015 | P0 | U01 点击“接受报价” | 状态变为 `accepted`；打样申请进入 `unpaid`，显示“支付打样费” |
| C-016 | P0 | 重复点击“接受报价” | 第二次返回明确冲突或已处理提示，不重复产生订单、不重置已支付状态 |
| C-017 | P0 | U01 创建打样费支付订单 | 支付金额取服务端报价，客户端不能修改金额；订单号唯一，状态为 `pending` |
| C-018 | P0 | 完成微信支付并接收成功回调 | 报价申请变为 `paid`；记录支付时间和订单号；重复回调不重复处理 |
| C-019 | P0 | 支付成功后刷新小程序 | 显示支付成功和下一步生产状态；不再显示“支付打样费”按钮 |
| C-020 | P0 | A01 根据已支付打样申请创建生产工单 | 工单关联用户、作品、报价和产品参数，状态可进入待生产 |
| C-021 | P0 | A01 分派供应商并开始生产 | 记录供应商、生产状态和操作人；用户能看到当前进度 |
| C-022 | P1 | A01 上传打样照片或质检结果 | 文件与生产工单关联，用户可查看；非法文件类型被拒绝 |
| C-023 | P1 | A01 标记发货并填写物流信息 | 状态变为已发货，用户可查看物流单号 |
| C-024 | P1 | U01 确认收货 | 状态变为完成；重复确认不改变已完成订单 |

## 5. 登录、权限和数据隔离

| 编号 | 优先级 | 操作 | 预期结果 |
|---|---|---|---|
| S-001 | P0 | 未登录访问商品、会话、报价接口 | 返回 401，不返回业务数据 |
| S-002 | P0 | U02 访问 U01 的会话 ID | 返回 404 或无权访问，不泄露会话是否存在 |
| S-003 | P0 | U02 访问 U01 的作品 ID并提交报价 | 返回拒绝，数据库不产生申请 |
| S-004 | P0 | U02 访问 U01 的报价申请并接受报价 | 返回拒绝，U01 的状态不变 |
| S-005 | P0 | 普通用户访问管理员报价和审核接口 | 返回 403，不执行任何写操作 |
| S-006 | P0 | 使用过期或篡改 Token 请求 | 返回 401，不执行数据库写操作 |
| S-007 | P0 | 连续快速点击提交报价 5 次 | 至少有防重复机制；不能产生相同业务内容的重复申请 |
| S-008 | P0 | 退出登录后返回上一页再次提交 | 返回 401，不接受旧登录态 |

## 6. 对话创作和数据留存

| 编号 | 优先级 | 操作 | 预期结果 |
|---|---|---|---|
| D-001 | P0 | 创建新会话后关闭页面 | 会话可恢复，已完成步骤和输入仍存在 |
| D-002 | P0 | 同一会话重复提交同一步 | 不产生错误顺序；最新有效数据可查询，历史事件可追溯 |
| D-003 | P1 | 输入超长文字、空文字和特殊字符 | 空值按规则拦截；超长值被限制；不发生 SQL 错误或页面崩溃 |
| D-004 | P1 | 上传非图片文件或超大图片 | 前端和后端均拒绝，并提示限制；不保存无效文件记录 |
| D-005 | P1 | AI 服务超时或返回失败 | 显示可重试状态，之前的会话参数和作品不被清除 |
| D-006 | P1 | 生成失败后再次生成 | 积分只按实际成功规则扣除，失败重试不重复扣费 |
| D-007 | P1 | 小程序点击查看 3D、换材质 | 只提示电脑端地址 `https://www.zhijiansk.com/`，不调用小程序不支持的 3D 能力 |

## 7. 报价、状态和支付异常

| 编号 | 优先级 | 操作 | 预期结果 |
|---|---|---|---|
| P-001 | P0 | A01 只填写单价，不填总价或交期 | 不允许进入 `quoted`，用户不能接受报价 |
| P-002 | P0 | A01 填写 0、负数、超大金额 | 校验失败，不保存非法报价 |
| P-003 | P0 | 用户接受已拒绝、已接受或已关闭报价 | 返回冲突提示，状态不变 |
| P-004 | P0 | 客户端提交自定义支付金额 | 服务端忽略客户端金额，金额必须从报价记录读取 |
| P-005 | P0 | 同一报价连续创建支付订单 | 返回已有待支付订单或安全复用，不产生重复待支付订单 |
| P-006 | P0 | 支付取消或支付失败 | 状态回到可重试的未支付状态，不误标记为已支付 |
| P-007 | P0 | 微信支付成功回调重复发送 | 业务状态只从未支付变为已支付一次，不重复创建生产工单 |
| P-008 | P0 | 伪造支付回调金额或订单号 | 签名、订单号、金额校验失败，不更新业务状态 |
| P-009 | P0 | 查询不存在的支付订单 | 返回 404 或明确不存在，不泄露其他用户订单信息 |
| P-010 | P1 | 支付成功但客户端网络断开 | 重新进入页面可通过服务端查询到正确支付状态 |
| P-011 | P1 | 已支付订单再次点击支付 | 不创建新支付订单，提示已支付或进入下一步 |
| P-012 | P1 | 退款后刷新申请和订单 | 业务状态与退款结果一致，不能继续按已支付状态生产 |

## 8. 代销和版权

| 编号 | 优先级 | 操作 | 预期结果 |
|---|---|---|---|
| CSG-001 | P0 | U01 选择代销但不关联自己的作品 | 提交失败 |
| CSG-002 | P0 | 不确认版权声明提交代销 | 提交失败 |
| CSG-003 | P0 | 版权依据选择“已授权”但不填授权来源 | 提交失败 |
| CSG-004 | P0 | 选择目录渠道并提交代销 | 创建申请，默认预售模式，状态为 `pending_review` |
| CSG-005 | P0 | 页面展示渠道名称 | 同时显示“目录记录不代表已合作或已获授权”提示 |
| CSG-006 | P0 | A01 审核通过代销申请 | 状态变为 `approved`，保留审核人、时间和备注 |

## 9. 上线阻断条件

以下任一项失败，不能上线真实用户：

- C-001、C-011、C-013、C-015、C-017、C-018、C-020
- S-001 至 S-006 任一项
- P-004、P-007、P-008 任一项
- CSG-001 至 CSG-005 任一项
- 支付成功后无法查询状态，或重复回调重复创建业务数据
- 用户能看到其他用户作品、报价、订单或支付信息
- 生产订单没有明确的责任人、供应商和状态

## 11. 首轮执行顺序

第一轮只执行 P0：登录、对话创作、作品保存、报价、接受报价、支付、支付回调、生产工单和权限隔离。

第二轮执行 P1：多视图、3D 跳转、上传、物流、退款、版权补充材料和代销审核。

首轮建议只使用“合金冰箱贴 + U01 + 一家测试供应商”，跑通一笔完整打样订单后，再录入其他产品和真实渠道。
